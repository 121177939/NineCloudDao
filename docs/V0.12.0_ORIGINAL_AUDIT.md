# V0.12.0 FINAL 初稿复核结论

## 结论

原始 `V0.12.0 FINAL` 压缩包能够正常解压，JavaScript也能通过基础语法检查，但**数据库安全边界与关键玩法闭环不完整，不应继续部署**。本次以 `V0.12.0 FIX1` 完全取代初稿。

## 已确认的关键问题

1. **内部加资源函数默认可执行**  
   初稿中的 `casino_credit`、`casino_debit`、`casino_available`、`casino_result`、`settle_casino_duels_v1` 等函数未撤销 `PUBLIC/anon/authenticated` 的默认执行权。尤其 `casino_credit(uuid,text,bigint)` 可绕过正式玩法直接增加灵石或修为，属于阻断上线的安全问题。

2. **修为输钱没有同步小境界**  
   初稿只减少 `player_characters.cultivation`，没有重新计算 `realm_stage_id` 和 `character_cultivation_state.base_rate_per_second`，因此“可以跌小境界、不能跌出当前大境界”没有真正落地。

3. **无人应局的赌注可能长期锁死**  
   初稿只在列表中隐藏超过30分钟的公开赌桌，没有自动取消和返还，也没有创建者主动取消RPC。

4. **五分钟开奖结果信息不完整**  
   初稿结算只写“胜负已分”，没有向双方返回各自招式、对手招式和本人输赢结果。

5. **造化彩池只有累计，没有开奖**  
   没有造化签、开奖轮次、中奖人、奖池发放和历史记录，因此5%进入彩池后无法形成闭环。

6. **赌场限制没有落到数据库**  
   缺少元婴期准入、修为最低50,000、单注20%上限、每日场次、贪念冷却、玩家只能存在一张进行中赌契等服务器校验。

7. **检查SQL过弱**  
   初稿检查SQL只检查少量对象是否存在，没有检查函数权限、危险旧函数、RLS、五分钟、5%入池、修为保护、返还与开奖规则。

8. **发布元数据未同步**  
   初稿压缩包中仍残留旧版本基线和缓存标识，可能导致PWA继续显示旧前端。
