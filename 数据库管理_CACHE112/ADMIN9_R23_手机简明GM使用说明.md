# ADMIN9 R23 手机简明GM使用说明

## 1. 这次为什么重做

R22的功能并不缺，问题是入口太散、技术字段太多、手机上要来回找。R23不重新发明后台接口，而是把原有能力重新编排成“先看状态 → 再做操作 → 最后看审计”的管理顺序。

R23继续复用R22全部既有RPC。制作时对R22和R23的字面RPC调用清单逐项比对：旧版59个，新版仍为59个，没有缺失，也没有为了界面重做偷偷增加一套平行接口。

## 2. 新导航

- 首页：版本、健康状态、最常用入口。
- 玩家与运营：玩家查询、资源发放/撤回、角色运营。
- 游戏控制：装备/世界BOSS、赌场。
- 内容与经济：配置、珍宝阁、内容工坊。
- 宗门管理：宗门基础、成长、人物/切磋、道侣、自主生态。
- 数据库：容量、24小时治理、Cron、异常、清理记录。
- 安全与技术：审计、回滚、函数/技术查看。

手机宽度下卡片与表单自动变成1—2列，不要求横向拖动大表格。

## 3. 数据库页日常怎么用

平时只需要三个动作：

1. 点“一键检查数据库”。先看当前容量、容量状态、自动治理、候选技术历史。
2. 如需手动维护，先保持“只预览，不实际删除”勾选，点执行，确认候选数量和保护项。
3. 确认无误才取消dry-run执行一次安全清理。所有实际清理仍通过旧ADMIN9安全RPC进入数据库白名单函数，前端本身不直接DELETE业务表。

不要在日常维护中使用TRUNCATE或VACUUM FULL。数据库变大时先找增长来源，而不是先调高容量警戒线。

## 4. 绝对不能清的数据

DBCAP03明确保护：

- 当前角色身份、境界、修炼、寿元、当前状态；
- 背包、装备、强化、器魂、法宝和所有正式资产；
- 命格、功法、永久成长；
- 当前宗门、弟子、关系、职位、建筑、仓库；
- 未完成交易和正在结算中的业务；
- processing / running / settling；
- 未领取、未展示；
- 有效或永久效果；
- 重大/置顶世界事件、重大宗门历史；
- 成就和主要历史记录。

## 5. R23和SQL241的关系

R23可以在SQL241前打开，但DBCAP03专用的24小时保护指标只有SQL241升级成功后才完整出现。SQL241门禁通过前，不要仅凭GM显示“CACHE112”就判断数据库已经完成升级。
