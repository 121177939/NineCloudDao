# 冲突与A线注意事项

1. **角色注册受保护区域**：候选只新增 `player_characters` 的AFTER INSERT五行分配触发器，没有替换注册函数。A线仍需核验与现有角色创建事务、RLS和触发器顺序是否冲突。
2. **服务端结算受保护区域**：挑战是独立新RPC，没有修改现有结算函数；正式接入前必须在测试Supabase验证行锁、并发、幂等和全事务回滚。
3. **天生剑心配置**：候选会把旧“战斗属性+10%且未启用”改为“剑类武器+剑系功法最终伤害+8%”。原配置已备份到 `ncd_b_module_backup.bcombat01_fates`，回滚SQL可恢复。
4. **装备系统缺失**：当前基线没有正式武器/衣服穿戴真相。候选适配表默认空值，因此未接装备模块的角色全部按赤手空拳、赤裸和0装备属性计算。不得把演示名称写死到角色数据。
5. **功法战斗语义**：候选读取普通功法1号槽作为攻击功法，读取2至5号槽中首个support功法作为防御功法；只有 `fixed_effects.combat_skill_multiplier`、`combat_damage_reduction`、`combat_school` 存在时才有额外战斗效果。A线需决定现有功法如何配置这些字段。
6. **战利修为暂存**：为保护现有修为硬上限，超额奖励进入暂存。A线应把领取RPC接到突破成功后或登录结算流程；候选客户端尚未增加独立暂存入口。
7. **旧榜单回归测试**：旧测试把战力榜固定判定为“暂未开放”。候选将该测试改为双模式兼容。正式接入时必须同步测试改动。
8. **九霄界闻**：候选只调用现有 `world_event_publish_v0140`，不覆盖它；仍需在真实库确认严格置顶、保留期和事件类型显示正常。
9. **SQL未真实执行**：本交付完成静态审计和模拟测试，但没有生产或测试Supabase连接，不能把静态通过视为数据库运行通过。
10. **排行榜实时计算性能**：候选RPC按查询时为符合条件的角色生成战斗快照。当前角色规模下便于保证权威一致；若角色量显著增长，A线应做真实数据库压测，并评估服务端可重算战力快照、索引或增量更新方案，不能直接把客户端上传的战力作为权威值。
