# 九霄问道 V1.7.5 CACHE51｜GitHub轻量部署包

本版本基于 **V1.7.4 CACHE50**，重做“灵骰问道”公共牌桌，并同步升级鱼虾灵局单一庄家、玩家庄联合承保、100:95 / 100:97.5结算与造化池开奖规则。九霄灵牌规则不在本版本修改范围内。

## 主要内容

- 灵骰问道改为10秒公共轮次：一名庄家对多名闲家，同轮共享一组三骰，可押大、小、豹子、1～6。
- 灵骰多人下注使用120ms点击合并 + 批量RPC；前端倒计时本地运行，只在开奖/换局边界读取权威状态，不做1秒数据库轮询。
- 鱼虾灵局同样使用批量下注RPC，并取消“玩家庄存在时仍可切换荷老”的双庄入口。
- 荷老系统庄按100:95体系：鱼虾95/190/285；灵骰大小95、数字95/190/285、任意豹子3325。
- 玩家庄对称100:97.5：输家承担标准责任100%，赢家取得97.5%，2.5%固定进入赌场。
- 玩家庄无法独立承保、但仍可承担50%时，本轮后续触发玩家庄+荷老50/50联合庄；本轮结束后玩家自动下庄并按角色冷却30分钟。连50%也承担不起时，荷老接管新责任。
- 玩家庄/联合庄下注使用80灵石整数步进，避免2.5%手续费和50/50分配产生小数灵石。
- 赌场有正利润时仍将50%利润加入造化池；无正利润时本期不追加利润，但已有造化池仍照常开奖。
- V1.7.4装备常驻6×6背包、洞府单一6×6储物格及洞府资源条去重继续保留。

## 正确升级顺序

1. 在Supabase SQL Editor执行 `104_V1.7.5_灵骰公共牌桌与联合庄资金结算.sql`。
2. 解压本GitHub部署包，覆盖仓库根目录并提交`.github`，推送`main`。
3. 等GitHub Actions的build/deploy成功后，执行 `105_V1.7.5_CACHE51_正式切换与发布门禁.sql`；该SQL会关闭旧“灵骰即时开奖”RPC入口。
4. 执行只读 `106_V1.7.5_CACHE51_升级后检查.sql`，确认所有`ok`均为`true`。
5. 手机端完全关闭旧页面后重新打开；CACHE51会清理旧前端缓存。

SQL不包含在本GitHub ZIP内，请使用独立 `Jiuxiao_V1.7.5_CACHE51_SQL.zip`。

`B_HANDOFF/`仅供B线开发交接；Pages白名单构建不会发布该目录。

- 性能硬锁：公共桌下注成功只返回轻量增量（本批下注+最新余额+庄家模式补丁），不得在持有赌场资金锁时聚合整桌/20局历史；完整状态仅在阶段边界读取。
- 多人边界同步：开奖/换局权威读取在客户端增加40～200ms轻量抖动，削平同一整点的并发请求尖峰，不改变服务器封盘时间。
