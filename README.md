# 九霄问道 V1.7.6 CACHE55｜多人牌桌性能版

正式源码基线：V1.7.5.3 CACHE54。数据库最低基线：V1.7.5 CACHE51（104 FIX1 + 105 + 106）。

## 本版内容

- 正式并入 `B-PAIGOW02_UI01`，替换九霄灵牌视觉层；牌九发牌、私牌、大小牌九、荷老庄、玩家庄和结算规则不变。
- 灵骰公共桌针对多人同时下注重构：已存在轮次无锁快路径、旧局维护非阻塞、最近历史集合聚合、共享赌场资金锁缩到事务末尾。
- 灵骰下注成功只局部更新DOM，不再每个批次重建整张牌桌；阶段边界只同步1条新历史并增量合并。
- 灵骰倒计时大部分时间低频本地更新，仅开骰窗口提高动画频率；公共赌场桌打开时暂停非紧急后台网络同步。
- 九霄灵牌Realtime突发事件合并到单个动画帧重绘；阶段到期兜底改用非阻塞单推进者；安全校准降频。
- 不修改V1.7.5现有赔率、100:97.5玩家庄手续费、联合庄、奖池、牌九规则。

## 推荐部署方式（避免旧仓库Merge冲突）

1. **先执行SQL 107**：`107_V1.7.6_多人牌桌性能重构.sql`。
2. 建议重新克隆一次正式GitHub仓库到全新目录；不要把CACHE55和旧本地分支做Merge。
3. 保留新克隆目录里的 `.git`，用本ZIP内容完整覆盖仓库根目录（包含 `.github`）。
4. 提交并推送 `main`，确认GitHub Actions的 `build` 与 `deploy` 两个Job均绿色成功。
5. **再执行SQL 108**：正式切换发布门禁到 `V1.7.6 CACHE55`。
6. **最后执行SQL 109**：所有检查项 `ok=true`。
7. 手机彻底关闭旧网页后重新打开；CACHE55使用独立cache epoch 55。

若107失败，不要继续GitHub部署和108/109；先处理107报错。

## 性能原则

- 不恢复1秒数据库轮询。
- 不让所有客户端同时阻塞等待牌桌阶段推进。
- 不在每笔下注后读取20局历史或重建整张公共牌桌。
- 不使用全局fetch劫持、长期MutationObserver扫页或无界DOM历史。
- Pages产物不包含 `B_HANDOFF/` 或SQL。
