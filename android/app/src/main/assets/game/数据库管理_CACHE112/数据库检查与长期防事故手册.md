# 数据库检查与长期防事故手册

## 一、CACHE112上线当天检查顺序

### 上线前

1. 保存当前生产数据库备份/快照。
2. 运行随包 `数据库健康检查_只读.sql`，把完整JSON结果保存为“上线前基线”。
3. 记录数据库总大小、Top10表、xact_rollback、temp_bytes、deadlocks、Cron清单。
4. 确认没有启用 `paigow_tick_due_rooms_bpaigow01` 的秒级/分钟级Cron。

### SQL241升级后、门禁前

1. 打开ADMIN9 R23 → 数据库 → 一键检查数据库。
2. 确认所有保留天数为1、batch=20000。
3. 确认全局维护只有一个 `jiuxiao-auto-cleanup-v210`，计划为 `25 */6 * * *`。
4. 确认BSECT06维护只有一个 `jiuxiao_bsect06_daily_maintenance`，计划为 `35 */6 * * *`。
5. 保持dry-run，运行一次安全候选预览。
6. 检查保护项中 processing/running/settling、未领取/未展示、永久效果、重大/置顶事件是否仍有明确保护统计。
7. 实机检查游戏核心功能后，再执行SQL241制度门禁。

只有门禁返回 `SQL241_GATE_PASSED`，才把数据库正式记为SQL241/CACHE112。

## 二、上线后固定观察点

建议在 **1小时、6小时、24小时、48小时** 各运行一次 `数据库健康检查_只读.sql` 并保存结果。

重点比较：

- `database_size_bytes`：看增长斜率，不要求每次都下降；PostgreSQL删除行后文件也不一定立即缩小。
- `top_10_tables` 与 `key_table_stats`：同一技术历史表是否持续线性膨胀。
- `last_24h_cleanup.failed_count`：应为0。
- `recent_cleanup_runs`：每6小时应持续出现正常运行；不能出现大量重复Cron。
- `xact_rollback`：看增量是否异常，而不是只看历史累计值。
- `deadlocks`：上线后最好不再增长；只要增加就要查对应时间段。
- `temp_bytes` / `temp_files`：看24小时增量是否仍然异常大。
- autovacuum / autoanalyze时间：关键大表应保持正常，不要因清理任务把它关闭。

如果数据库启用了 `pg_stat_statements`，再运行 `PERF热点RPC与临时IO_只读_可选.sql`：

- 看 `enforce_single_game_session_v1` 的新增调用是否明显下降；
- 看修炼/机缘/通知/市场/世界事件RPC是否不再由固定空转主导；
- 看 `paigow_tick_due_rooms_bpaigow01` 是否仍无固定高频调用；
- 看Top temp I/O查询是否出现新的大JSON/全表排序热点。

## 三、哪些情况算红灯

- 48小时后数据库仍持续近似线性快速增长，且Top10表里出现新的append-only技术表。
- 同名维护Cron出现2个或更多。
- 全局/BSECT06维护不再每6小时运行，或连续failed。
- 牌九秒级/分钟级tick再次启用。
- deadlocks继续增加。
- temp I/O短期激增。
- 新模块表把完整dashboard、大数组、可重建结果长期塞进JSONB。
- 为了“解决容量”有人直接提高470MB阻断线，而没有先找增长源。

## 四、出现异常先做什么

1. 先用ADMIN9把自动历史治理 `enabled` 关闭，阻止问题继续自动执行。
2. 保存数据库健康检查JSON和错误信息。
3. 不要直接DROP/TRUNCATE玩家业务表，不要日常执行VACUUM FULL。
4. 不要改写已经执行过的历史SQL；追加下一编号修复SQL。
5. 根据Top10表和热点RPC定位是哪一个新模块没有遵守数据库准入规则。

## 五、每次以后开发新模块都要问的8个问题

1. 这张表是当前正式状态、永久历史、技术历史，还是临时状态？
2. 如果会持续追加，TTL/硬上限/汇总策略是什么？
3. 什么状态绝对不能删？
4. 是否真的需要JSONB？是否在重复缓存可重建的大结果？
5. 玩家不操作时是否仍每30/60秒写数据库？能否改为时间戳/next_due/按需？
6. 清理条件是否有索引？是否LIMIT + SKIP LOCKED分批？
7. Cron是否低频、唯一、可审计？
8. 100名玩家运行24小时预计新增多少行、多少MB、多少固定RPC？

答不清这8项的新模块，不应直接进入生产。
