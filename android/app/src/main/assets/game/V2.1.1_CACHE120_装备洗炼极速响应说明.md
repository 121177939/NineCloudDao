# V2.1.1 CACHE120 · 装备洗炼极速响应

## 问题
CACHE119为了防止背包位置误判，在每次兵魄/护道/百炼前后串行执行多轮装备刷新、实时位置查询与forge overview刷新。一次点击实际可能经历5—6轮网络往返，移动网络下常见5—8秒反馈。

## 修复
- 兵魄/护道/百炼点击后直接调用SQL246权威事务RPC。
- 不再在客户端提交前串行调用 `B_EQUIPMENT01.refresh(true)` + `get_equipment_forge_item_state_v247`。
- 安全性不降低：SQL246服务端RPC本身在扣除前对角色归属、`location=backpack`、装备锁、材料、锁玉、灵石全部强校验，并原子提交。
- RPC返回已经包含最新 `sockets / material_after / lock_item_after / spirit_stones_after`，CACHE120直接用返回值原地更新孔位与资源。
- 成功反馈不再等待forge overview和装备主列表二次刷新；关闭弹窗后再按原有dirty机制同步装备主列表。
- 打开淬炼弹窗不再额外执行完整装备刷新+实时位置RPC；实际提交仍由服务端最终裁决。
- 成功状态会显示本次RPC端到端耗时（ms/秒），便于以后直接判断网络/数据库耗时。

## 数据库
SQL247 R2继续保持已上线；CACHE120不新增SQL，下一数据库编号仍为SQL248。
