# CACHE113 / ADMIN9 R25 / SQL243 升级说明

## 玩家端修复
- 装备淬炼弹窗新增内联状态，不再因toast被弹窗遮挡而表现为“护道灵玉点击无反应”。
- 全局toast层级提升到淬炼弹窗以上。
- 穿戴中的装备禁止孔位属性洗炼与百炼整装等级重炼；必须先卸下回背包。前端按钮禁用，SQL243 服务端同样执行 `EQUIPMENT_V210_BACKPACK_ONLY` 强校验。
- 洗炼成功后继续调用服务端装备战斗值重算，并原地刷新孔位与材料/灵石余额。
- 战斗回放支持服务端 `is_hit=false` / `hit=false` / `missed=true` 的闪避结果；秘境敌方事实区支持显示命中与闪避。

## SQL243
- 兵魄道玉属性洗炼默认额外扣 200000 灵石。
- 护道灵玉属性洗炼默认额外扣 200000 灵石。
- 百炼玄铁等级重炼默认额外扣 200000 灵石。
- 三项数值独立存于 `equipment_socket_settings_v210`，ADMIN9 R25 可分别修改。
- 材料、锁孔定灵锁玉和灵石在同一RPC事务中扣除，失败自动回滚。
- 新增 `admin9_verify_combat_socket_integration_v243()`：从生产库 `pg_get_functiondef` 检查天命榜挑战、预览与秘境结算函数的真实接入。

## 重要门禁
当前资料包缺少 SQL233 天命榜/秘境函数的原始SQL函数体，所以本轮没有伪造或猜写生产战斗核心。SQL243门禁会在生产库直接验证：天命榜挑战必须体现命中/闪避，天命榜或预览必须体现V2.1装备接入，秘境必须体现对战斗核心的复用。任一关键条件未证明，门禁报错并拒绝把发布控制更新为 CACHE113。

## 执行顺序
1. SQL242升级
2. SQL242门禁 -> `SQL242_GATE_PASSED`
3. 部署CACHE113网页/Android与ADMIN9 R25
4. SQL243升级
5. SQL243门禁 -> `SQL243_GATE_PASSED`
