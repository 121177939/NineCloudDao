# SQL255 R2 执行说明 · V2.2.0 CACHE124 / 天墟

当前生产数据库已经确认 `SQL254_GATE_PASSED`。SQL255 R1 本次执行在创建装备托管保护包装函数时因生产装备移动 RPC 签名与 R1 假设不一致而报错：

`function public.move_equipment_item_bequipment01_pre_v255(uuid, text) does not exist`

R1 位于单事务 `BEGIN ... COMMIT` 内，错误发生在 `COMMIT` 前，因此整次执行回滚，SQL255 仍未上线，数据库编号继续使用 SQL255，不跳 SQL256。

## R2 修复

R2 不再假设生产 `move_equipment_item_bequipment01` / `set_equipment_lock_bequipment01` 必须恰好是两个参数。脚本会从 `pg_proc` 自动寻找“前两个参数分别为 uuid+text / uuid+boolean，且其余参数均有 DEFAULT、因此仍可由现有两参数客户端调用”的生产重载，重命名保存原实现，再建立两参数托管保护入口。

重命名后的原实现会撤销 anon/authenticated 执行权，避免玩家绕过天墟托管保护直接移动或解锁已挂牌装备。

## 执行顺序

1. 不要重复执行 SQL254。
2. 不要再执行 SQL255 R1。
3. 在 Supabase SQL Editor 中完整执行 `01_SQL255_R2_V2.2.0_CACHE124_赌场退役_天墟自由交易_装备RPC自适应_执行即门禁.sql`。
4. 最后必须看到 `SQL255_GATE_PASSED`。
5. 如果任何位置报错，SQL255 仍不能记为 ONLINE；把完整错误发回继续修 SQL255。
6. 只有 `SQL255_GATE_PASSED` 后才把生产基线推进为 SQL255 ONLINE；下一条数据库编号才是 SQL256。

CACHE124 / ADMIN9 R34 的客户端与 GM 不需要因为本次 SQL 修复升版本。
